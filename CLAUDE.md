## What this is

**voice-board**: a whiteboard that draws from natural-language commands. A small, fast LLM ("System 1") turns each command into **typed board actions** (`add_shape`, `add_arrow`, `add_dimension` (measurement line + label like "10 ft": `target` = vertical line beside an element's height, or `axis: "width"`; or `from`+`to` = horizontal line across the gap, vertical if stacked; unbound arrow with bar ends, `customData.kind: "dimension"`, so it does not follow moved shapes), `animate_element` (`toward`/`away_from`/`direction`/`placement`, `speed`, `style`: same end state as a move, but the runner tweens it), `scroll_view` (moves the camera, not the board), `zoom_view` (camera zoom: a level in percent or a step in/out, optionally on an element), `generate_diagram` (a whole diagram: nodes + edges in one call, laid out by dagre), `plot_graph` (y = f(x) curves), `add_chart` (column/bar/line/area/pie/donut), `move_element`, ...). The server streams them over SSE; the browser validates and applies them to an [Excalidraw](https://github.com/excalidraw/excalidraw) canvas as they arrive.

**Status: milestone 1 of 5** (typed text commands only), plus an optional local fast path (sidecar: strict-grammar code rules, then a fine-tuned Laya model; early M4 work) built-in clip-art objects (`add_object`, early M3 work) and motion (`animate_element`; rules + cloud only, teaching Laya motion is a planned follow-up: an `animate` action option + destination question, motion templates in `make_train.py`, retrain, a motion eval set) and view scrolling/zooming (`scroll_view`, `zoom_view`; rules + cloud only, same Laya follow-up: action options + direction/level/target questions in `decide.py`, templates in `make_train.py`, retrain, a scroll/zoom eval set). Voice input is M2: local Moonshine STT works (mic button -> `stt/` sidecar), and so do Deepgram/AssemblyAI cloud STT (relayed by the API server) and the browser's Web Speech API, switchable in Settings (see Voice input under Architecture); the mic pauses recognition after a silent spell and resumes on speech (idle pause, see Voice input); still to do are push-to-talk and an enrolled-speaker gate to ignore other voices; M3 is diagram generation (`plot_graph` equation graphs and `add_chart` data charts with hover readouts and a by-hand data editor done, rules + cloud only; `generate_diagram` done: graph -> dagre layout -> ordinary shapes/arrows; not done: Mermaid input, a "System 2" planner model for big diagrams, routed (non-straight) arrows) and images (photo search, uploads, free resize; not started); noise/intent filtering and a fine-tuned router M4; persistence/auth/export M5. Roadmap, rationale and licence notes are in [docs/PLAN.md](docs/PLAN.md) (a planning doc, partly unverified; not a spec of current code).

## Stack

- npm workspaces monorepo (`shared`, `server`, `web`), TypeScript (strict, ESM, `moduleResolution: Bundler`), Node 22+.
- **server**: Fastify 5, `@anthropic-ai/sdk`, `openai`, zod 4, `ws` (cloud speech relay). Run with `tsx`.
- **web**: React 18, Vite, `@excalidraw/excalidraw` 0.18, `@dagrejs/dagre` 3 (MIT, sync layered layout for `generate_diagram`), lucide-react, `@iconify-json/fluent-emoji-flat` (dev, clip-art source). Tests: vitest + jsdom.
- **shared**: zod schemas + protocol types, consumed as TS source (`main`/`types` point at `src/index.ts`; no build step).
- Prettier: `printWidth: 140`.

## Architecture / request flow

```
web: CommandDock -> useCommandRunner.run -> summarize(scene) -> POST /api/command {text, scene}
server: app.ts validates body (zod) -> provider.run -> [withFastPath: POST sidecar /decide: rules -> Laya; fast/ignore answered locally]
        -> toolRouter.groupsFor(text, scene) picks the tool groups -> ONE streaming model call (those tools only, no tool-result round trip)
        each completed tool call -> parseAction (zod) -> SSE `data: {CommandEvent}`
web: streamCommand parses SSE -> consume() -> executor.applyAction -> api.updateScene (one undo snapshot per command)
     (animate_element: applyAction returns the end state + `animation`; consume awaits animate.ts#playAnimation before the next action)
     (scroll_view / zoom_view: never reach the executor; consume runs view.ts#planScroll / planZoom -> await playScroll, then refreshes ctx.viewport)
```

- The **zod schemas in `shared/src/actions.ts` are the single source of truth**: they generate the model tool definitions (`z.toJSONSchema(..., { io: "input" })`) and validate every incoming tool call. Never hand-write tool JSON; change the schema.
- **SSE events** (`shared/src/protocol.ts` `CommandEvent`): `route {source: local|cloud, model, detail, ms, objects?}` (always first: who decided and why; shown as the Local/Cloud badge in the activity panel; `objects` = the cloud provider's ObjectMode, shown as "objects: enum|text" in the route note), `action {action, ms}`, `say {text}`, `invalid {name, error}`, `error {message}`, `done {ms, model, actions, tools?, tokens?}` (`tools` = `["all"]` or `["core", ...groups]`; `tokens` = `TokenUsage {in, out, cached?}` summed over the command's model requests: Anthropic `usage` with cache reads/writes counted as sent (`system1.ts#usageOf`), OpenAI from `stream_options.include_usage` on the stream's last, choice-less chunk (`addUsage`; an endpoint that rejects `stream_options` would now fail). Both show in the route note as "tools: core+chart · tokens: 8.2k in, 95 out" (`ActivityPanel#fmtTokens` rounds; hover for exact and cached counts).
- **Barge-in**: a new command aborts the in-flight fetch; the server aborts the model call on `res` close. Cancelled runs are marked `cancelled`. Spoken commands don't barge in on each other: `App.tsx` chains them (`onSpoken`), so each waits for the previous one.
- **Voice input** (`web/src/voice/useVoice.ts` + `stt/server.py` or `server/src/stt.ts`): `speechConfig(settings, health)` picks the provider on each mic start (Settings choice -> health's `stt.provider` = `STT_PROVIDER` -> moonshine). Moonshine connects to `/stt` (the sidecar); Deepgram/AssemblyAI connect to `/api/stt` on the API server, which speaks the **same protocol** (the `start` message adds `provider` and the browser's `apiKey`; else the .env key for that provider, never another's). `stt.ts` converts float32 frames to int16 PCM, buffers them until the upstream socket opens, and turns upstream messages into lines: `DeepgramLines` (is_final pieces joined until `speech_final`/`UtteranceEnd`/`from_finalize`; nova-3 `keyterm` params at connect only, since mid-stream updates are Flux-only) and `AssemblyLines` (v3 `Turn`, final at `end_of_turn && turn_is_formatted`, key terms updated mid-stream with `UpdateConfiguration`). AssemblyAI turn detection comes from Settings `speech.assemblyTurn` (`AssemblyTurn` in shared/protocol.ts: `confidence`, `minSilenceMs`, `maxSilenceMs`; `speechConfig` adds it as `turn` for assemblyai only, `start` carries it, the server re-clamps it with `cleanAssemblyTurn` and sends only the fields given as `end_of_turn_confidence_threshold`, `min_end_of_turn_silence_when_confident`, `max_turn_silence`; unset = AssemblyAI's defaults, listed as `ASSEMBLY_TURN_DEFAULTS` 0.4/400/1280 from its docs, not checked against the live API). Deepgram's `endpointing` 300 ms / `utterance_end_ms` 1000 are hard-coded in `upstreamFor`. Finals that end mid-command are joined in the browser, see **Line joining** below. `stop` sends Finalize+CloseStream / ForceEndpoint+Terminate, and the line in progress is flushed as a final when upstream closes. The upgrade is refused (403) when `Origin` doesn't match `Host`: WebSockets skip CORS, so another site could otherwise use the .env key. `browser` (`voice/browserSpeech.ts`): `(webkit)SpeechRecognition`, continuous + interim, `lang` en-US, no getUserMedia/worklet/socket; `listenInBrowser` emits the same `SttMessage`s (final result = line, non-final ones = the partial; ids `<run>-<index>`), starts a new recognition whenever the browser ends one (after pauses / ~1 min), and ends with a message on fatal errors (not-allowed, network...) or 3 ends within 1 s each. No key terms (Chrome ignores `grammars`; `phrases` is on-device only). Untested in a real browser so far. Moonshine path: mic button (CommandDock) -> `getUserMedia` (echo cancellation/noise suppression/AGC on) -> inline AudioWorklet (Blob URL) posts ~100 ms Float32 frames at the AudioContext's own rate -> WebSocket `/stt` (Vite `ws: true` proxy to 127.0.0.1:8789) -> Moonshine streaming model (does its own VAD and resampling) -> `partial` messages shown as the input's placeholder, `final` -> `LineJoiner` -> `isCommand` (has a letter/digit) -> `runner.run` via the queue above. **Line joining** (`useVoice.ts#LineJoiner`, every provider): a final that `looksIncomplete` (last word in `JOIN_WORDS` (and/with/to/the/labelled/...; words that also end real commands like in/up/over/below/that are left out), or ends in , : ; - ...) is held and shown with "…"; the next final is joined to it (`joinLines`: held line's full stop dropped, case kept) and checked again. A held line runs as it is after `HOLD_MS` 1.5 s with no speech, or `HOLD_SPEAKING_MS` 8 s once a partial shows the speaker carried on; `end` (stop/error) and doze flush it, unmount drops it. A false hold only costs 1.5 s. Only finals run: partials are often wrong mid-line ("blueprint" before "blue box"). Frames captured before the socket opens are buffered and flushed after `start`. Stop sends `{type:"stop"}`, which completes the line being spoken (it still runs) and then closes; a 3 s timeout ends the session anyway. `boardKeyterms` (`COMMAND_KEYTERMS` ("draw", "flower": always first, words STT often gets wrong) + text/shape labels, no clip-art names, commas stripped, ≤ 50 total) go out on `start` and again whenever a new line starts and they've changed; Moonshine's `set_keyterms` then spells them like the board ("Postgres", not "postgres"). The sidecar loads one `Transcriber` and makes a `Stream` per WebSocket. All native calls go through `Engine.call` (asyncio lock + `to_thread`), and the worker feeds any backlog to `add_audio` as one chunk. It never cancels a native call mid-pass; on disconnect it waits for the pass, then closes the stream. A new connection closes the previous one ("Listening moved to another tab."), because key terms are per transcriber. **Idle pause**: `speechConfig` adds `idleMs` (Settings `speech.idleSeconds`, default `IDLE_SECONDS` 10, 0 = never) and `wakeRms` (`speech.wake` high/normal/low = `WAKE_DBFS` -50/-42/-34 dBFS per ~100 ms frame; guesses, not tuned on a real mic). Any ready/partial/final restarts the idle timer; when it fires, the session goes to `VoiceState` `dozing`: the socket is just closed (no `stop`: nothing has been said, so there's no line to finish) or the browser recognition aborted, and the mic stays open (for `browser` it's opened just for this). Frames go to `WakeDetector` (keeps the last `PREROLL_FRAMES` 20 = 2 s, wakes on `WAKE_FRAMES` 2 loud frames in a row), which reconnects and sends the pre-roll before the live frames. `browser` can't be given the pre-roll, so its first word can be lost. Clicking the mic while dozing ends the session. The hook's functions call each other (a message restarts the timer, which dozes, and waking reconnects), so they're built once in a `useMemo` and only use refs and setters; `s.frame` is where mic frames go (connect buffer, socket or wake detector). There's no speaker filtering yet.
- **Scene summary** (`web/src/board/summary.ts` -> `server/src/prompt.ts#formatScene`): compact text of ids, labels, positions, colour, selection, `recentIds` (newest first) so "it"/"that"/"the database" resolve. Capped at 500 elements / 100 selected / 50 recent by the server's body schema.
- **Objects / clip-art**: two catalogs. `shared/objects.json` (hand-curated: object name -> Fluent Emoji Flat icon name + aliases, 193) and `shared/objects-more.json` (generated and committed: every other icon of the set, minus skin-tone variants and icons whose name is a curated name, named "icon-name" -> "icon name", 1,392). `ACTION_SCHEMAS.add_object` is `AddObjectAny` (enum of `ALL_OBJECT_NAMES`, curated + more), so validation accepts both; the tools are built from `AddObject` (curated enum, `OBJECT_MODE=enum`, default; add_object = 3.2k of the 21.6k tool characters, generate_diagram 2.5k, add_chart 2.8k, plot_graph 2.3k) or `AddObjectText` (free-text `object`, 1.4k chars, `OBJECT_MODE=text`; 19.7k in all). In text mode `server/src/objects.ts#parseToolCall` maps the word with `matchObject` over both catalogs (exact phrase incl. a leading "a"; then articles dropped, name/alias, singular, shorter tails = head noun, unique one-letter typo; a name beats an alias, so "rose" is the rose, not curated "flower"; never a weak guess) or turns the call into an `add_shape` rectangle labelled with the word. Known miss: the tail rule can pick another sense ("cricket bat" -> the animal). Both tool sets are built once (`TOOLS_BY_MODE`, `OPENAI_TOOLS_BY_MODE`) so each stays byte-stable for caching. Aliases are used by `matchObject` and the sidecar's `draws_object` guard, never sent to the model; the sidecar (`fastpath/decide.py`) only knows the curated catalog. `web/scripts/build-objects.mjs` (`npm run objects --workspace web`, also run on predev/prebuild after the font copy) reads the `@iconify-json/fluent-emoji-flat` devDependency of `web` (pinned exactly, MIT), rewrites `shared/objects-more.json` (only when it changed) and `web/public/objects/<name-with-dashes>.svg` for both catalogs (~1,585 files, 6.3 MB) + `LICENSE.md`. That folder is gitignored like `web/public/fonts/`: offline once installed, and it can't drift from the catalog. Tests don't need it. An object is an Excalidraw `image` element with `fileId: "object:<name>"` (shared by every copy) and `customData {kind: "object", object}`; `labelOf` returns the object name, so the summary shows `image "tree"` and refs by name resolve. The executor never touches files: `loadObjectFiles(api)` (`web/src/board/objects.ts`) fetches missing ones, rasterizes them to 512px PNG and `addFiles` them, called after each `add_object` and once on load (localStorage keeps only elements). `update_element` on an object only resizes (`OBJECT_SIZES` 64/120/200, centre kept); colour/label throw `ActionError`.
- **Graphs and charts** (`plot_graph`, `add_chart`; `web/src/board/plots.ts` dispatches to `graph.ts` / `chart.ts`, shared bits in `plot-base.ts`): each is ONE `image` element (so move/resize/arrows/delete/undo work unchanged) whose `customData` is the full spec (`kind: "graph"|"chart"`, equations or labels+series, hex colours, ranges, title, unit, design size `w`/`h` from `PLOT_SIZES` 320x240/480x360/640x480). `fileId` = `graph:`/`chart:` + FNV hash of the spec, so a changed spec gets a new file. The executor stays pure; `loadPlotFiles(api)` renders missing files (spec -> SVG string -> `rasterize` PNG at 2.5x, max 1600 px) and runs after every applied action, after undo and on load (localStorage keeps only elements). The PNG is a white card, so it reads the same in dark mode. Equations: `shared/src/math.ts#parseEquation` (hand-written parser, no eval; also used by the schema's `superRefine`, so a bad equation is an `invalid` event); only y = f(x). The executor fits y with `fitY` (full extent, or the 2-98% quantiles when asymptotes blow it up, +6%) and stores it, so drawing and hover share exact ranges. Chart geometry comes only from `chartLayout(spec)` (render and hover both use it); the value axis includes 0 except for a line chart far from it. `update_element` on a plot: label = title, colour = first curve/series/slice (new file), size = `PLOT_SIZES[size].w`/scale (centre kept). **Editing chart data** = `add_chart` with `replace: <chart id>` and the complete new data: `replaceChart` respecs the same element (id, position, z-order, arrows kept; size only changes with `size`, centre kept); omitted title/unit/colours are kept (`title: ""` clears it); without `colors`, slices keep their colour by label and series by name (else position), new ones get the first unused default, and a pie <-> series-chart switch gets fresh defaults. For this the summary gives charts a `data` line (`summary.ts#chartData`: kind, JSON labels, each series JSON name + values, unit, colour names), which `formatScene` prints indented under the element; the prompt tells the model to copy it with only the change applied. **Editing chart data by hand** (`components/ChartEditor.tsx` + pure `board/chartDraft.ts`): an "Edit data" button over the one selected chart (also double-click it or press Enter: a window capture listener stops Excalidraw's image cropping for charts, and an injected `<style>` hides its "crop" hint while a chart is selected) opens a left-side panel: kind, title, unit, a labels x series grid (values kept as typed text, `parseValue` accepts "1,200"), colour swatches (per series, per slice for pie/donut), add/remove rows (≤ 24) and series (≤ 6), spreadsheet paste (`pasteCells`, tab-separated block from the cell pasted into), Enter = next row (adds one at the bottom), Ctrl+Enter = apply, Esc = cancel, and a live preview (`previewSpec` -> `renderChartSvg`). Apply builds the same `add_chart` + `replace` action the model sends (`draftToAction`, validated by the shared `AddChart` schema; colours always explicit) and runs it through `runner.applyActions`, so it is one undo step and an activity entry. Pie/donut use the first series; the others stay in the draft for switching back. The panel stops keydown/paste propagation so Excalidraw shortcuts don't hit the board; if the chart is deleted it closes, and if the chart changes elsewhere (voice) an untouched draft reloads, an edited one is kept and overwrites on apply. Hover: `components/PlotHover.tsx` listens to window `pointermove` (only an unpressed pointer whose target is the canvas, selection/hand/laser tool), `api.onScrollChange` and `api.onChange`, maps client -> scene with appState offset/scroll/zoom, and `hoverAt` (topmost element under the pointer; rotated plots skipped) returns a `HoverReadout` {heading, rows, marks in scene coords, anchor}; marks are drawn in an SVG with a scene->screen transform, the tooltip is HTML. State lives in that component, so Excalidraw never re-renders on mouse moves. The scene summary types them `graph`/`chart` with the title or equations as label (charts also carry `data`, see above).
- **Tool router** (`server/src/toolRouter.ts`, plain code): with `TOOL_ROUTER=auto` (default; per request `ModelConfig.tools`, Settings "Tools" Auto/All) a cloud request carries `CORE_TOOLS` (add_shape, add_text, add_arrow, move, update, delete, undo, clear; ~6.7k chars) plus the `GROUP_TOOLS` of each group `selectGroups(text, scene)` picks: `diagram` (generate_diagram), `object` (add_object; `objects.ts#mentionsObject`: 1-3 word n-grams in either catalog minus `NOT_OBJECTS` board words, picture/icon words, or "draw/add a <noun>" not in `BOARD_NOUNS`; text after labelled/called/saying, and "rename X to ...", is ignored), `dimension`, `motion`, `graph`, `chart` (also when a chart is on the board and the command names its labels/series (`editsChart`), has a digit or pie/line/bar/...), `scroll` (scroll_view + zoom_view; "zoom", "magnify", "actual size" and the scroll words; "zoom to 150%" also pulls in `chart` because of the "%"). Keyword regexes mirror the sidecar's `has_motion`/`has_plot`/`has_diagram`/`edits_chart` and err towards including (a wrong yes costs 1-3k chars; a miss makes the model approximate with shapes, which the subset prompt tells it to say). Each group's prompt bullets (`prompt.ts#GROUP_PROMPT`) and the chart `data` lines (`buildUserMessage(..., {chartData})`) only go with that group. Sizes (tools + system): all 27.4k chars, core 8.2k, core+scroll 10.3k (zoom_view adds 1.1k), core+object 11.7k. `toolsFor`/`openaiToolsFor`/`promptFor` memoise per group set; all groups = `TOOLS_BY_MODE`/`SYSTEM_PROMPT` exactly (byte-identical to the pre-router prompt). OpenAI follow-up turns reuse the first turn's set. Adding an action: put it in `CORE_TOOLS` or a group (and its keywords) or the router never sends it.
- **Prompt caching**: each tool-group set gives a byte-stable system prompt + tool list (`promptFor`/`toolsFor` are memoised; Anthropic path caches system + tools; the last tool of the set carries `cache_control`), so the cache is per set. Don't interpolate per-request data into the prompt; per-request data goes in `buildUserMessage`.
- **Model settings (UI over .env)**: `web/src/settings.ts` + `components/SettingsPanel.tsx` (gear next to the status pill). localStorage `voice-board:settings:v1` = `{active, customUrls, profiles}`; `active` is `server`, a preset id (anthropic/openai/cerebras/xai/groq/openrouter) or a custom OpenAI-compatible base URL; profiles are keyed by `endpointKey(provider, baseUrl)` (shared/protocol.ts: style + lowercased URL without trailing slash; empty URL = official API) and hold `apiKey, model, effort, objectMode, tools, models` (the endpoint's last-loaded model list). `requestConfig()` turns the active profile into `CommandRequest.config: ModelConfig` (undefined on `server` with no overrides). Server: `settingsFromEnv` parses .env once into `ServerSettings` (incl. `keys`: endpointKey -> .env key); `buildProvider(settings, config, factory)` layers the config over it per request (`buildApp` option `forConfig`, wrapped by the fast path too). **Security rule: a .env key is only used for its own endpoint** (`resolveEndpoint`), never for a browser-supplied URL. Model fallback: config model -> `SYSTEM1_MODEL` only on the .env endpoint -> official default (haiku / gpt-4.1-mini) -> else 400 "Choose a model". SDK clients are cached per endpoint+key (16). `POST /api/models {config}` lists `/models` through the SDKs (`listModels`, 10 s, no retries; needs a key). `/api/health` returns `HealthInfo` (.env provider, model, baseUrl, hasKey, `keyedEndpoints`, effort, objectMode, toolRouter, fastPath, `stt {provider, keyed}`; never keys). The status pill reflects the active profile (`effectiveModel`, `serverHasKey`). Keys sit in localStorage in plain text and the server calls any URL a browser gives it: fine locally, not for a public deployment.
- **Providers** (`server/src/provider.ts`): `Provider { name, model, hasKey, objects, tools, run, describeError }`. `providerFromEnv()` picks the .env backend. `system1.ts` (Anthropic: `messages.stream`, `eager_input_streaming`, `contentBlock` events) and `system1-openai.ts` (OpenAI: chat completions streaming; tool-call deltas stitched per `index`, flushed when the next call starts or the stream ends). `OPENAI_TOOLS` is derived from the Anthropic `TOOLS`, so both share one schema. **Follow-up turns (OpenAI path only):** gpt-oss on Cerebras ignores `parallel_tool_calls` and makes ONE call per request (verified from the raw stream; prompt wording and effort don't change it), so a multi-step command ("enlarge boy and draw flower") stopped after step 1. When a turn makes exactly one call and `looksMultiStep(text)` (comma/and/then/...), the call is answered with a tool result and the model gets another request, up to `SYSTEM1_MAX_TURNS`. Models that batch calls, and single-step commands, stay at one request. Every follow-up costs a request: Cerebras's free tier has a requests/minute limit (429 "Requests per minute limit exceeded", no Retry-After; the SDK retries silently, which looks like 60 s hangs), so a failed follow-up keeps the applied steps and emits an `error` event.
- **Local fast path** (optional, `server/src/fastpath.ts` + `fastpath/`): `withFastPath(provider, fast)` wraps a provider (sets `fastPath: true`, reported by `/api/health`). It POSTs `{text, scene}` to the Python sidecar; `fast` actions are re-validated with `parseAction` and streamed (`done.model` = `rules` or `laya:<checkpoint>`), `ignore` ends with 0 actions, and `llm`, a sidecar error/timeout or any invalid action falls through to the provider. Without a fast path, `app.ts` emits `route {source: "cloud"}` itself. The sidecar (`fastpath/server.py`, stdlib HTTP) has three tiers:
  1. **Rules** (`fastpath/rules.py#rule_command`, run on the real scene before any aliasing). It first normalises the command: fillers, stutters, leading "can you"/"let's", trailing "please", and self-corrections ("red, no wait, blue"; needs a no/wait/sorry/mean/actually marker, so "red or blue" isn't one). Then *every* word must be explained by one template: undo, clear, delete, recolor, resize (small/medium/large only), move (+ little/far distance), add_shape (colour/size/region/label), add_text (title/heading/caption/text + marker), rename (rename/relabel, "change the label of X to Y", or "change X to Y" only when X is a text element), add_arrow (connect/link/join, or "draw an arrow from/between"), animate ("<ref> [is] walks/runs/moving/strolls... towards/to/up to/away from <ref>", or "move/bring <ref> towards <ref>"; run/drive/fly/chase = fast, stroll/creep = slow; an adverb or second clause -> LLM), scroll (`scroll|pan [the page/view...] <dir> [a bit/a lot/a page]`, `move the view|screen|camera <dir>`, `go/scroll/jump/take me (back) to <ref>|the top/bottom/start/end` ("to the left/right" is a direction unless "all the way"), "scroll all the way <dir>" = edge, `show me|focus on <ref>`, "show everything"/"zoom to fit" = fit), zoom (`zoom in|out [a bit/a lot/more] [on|into|to <ref>]`, `zoom into <ref>`, `zoom [back|in|out] to <n>[%|percent|x|times]`, `set the zoom [level] to <n>`, `<n>% zoom`, each with an optional `on <ref>`; "reset the zoom"/"actual size"/"zoom back to normal" = 100; a bare number < 10 or outside 10-3000 -> LLM; tokenising drops "%" and splits "1.5x", so decimals go to the LLM), plus measurements and clear-verb objects. After the templates, `has_scroll` (scroll/pan/zoom/magnify/camera/viewport/canvas words) answers `llm` ("scroll needs the LLM") so Laya never turns a scroll into a move, and `has_motion` (a motion verb + towards/to/away/across, or move/bring + towards) answers `llm` ("motion needs the LLM"), because Laya has no animate_element and would turn it into a teleport. Then `has_diagram` (diagram/flowchart/architecture/workflow/pipeline/hierarchy/"org chart"/"mind map") answers `llm` ("diagram needs the LLM"); it runs after the templates, so "add a box labelled architecture" still goes fast, but a Laya-only edit of an element labelled with one of those words now goes to the cloud. Last, `has_plot` (`PLOT_WORDS` graph/plot/chart/equation/parabola/histogram/sine..., or an equation shape: `y =`, `f(x) =`, `x^`) or `edits_chart` (the command contains a label or series name, as whole words, from a `chart` element's `data`, e.g. "set Q2 to 20"; the unit is ignored) answers `llm` ("graph needs the LLM"); it is also checked before `object_command`, because "add a bar chart" otherwise matches the curated `bar chart` clip-art. Food words (pie, donut) are left out so "draw a pie" stays an object. An element reference is resolved with `resolve_target` on the reference's own words, and every word must be a filler, a kind word, the element's colour or a label word (groups only for delete/recolor/resize/move). Labels are ≤ 8 words with no second clause, placement or correction words; the user's casing is kept and the new id is a slug of the label. Objects can't be recoloured or renamed. Rules never answer `ignore`. They answer `model: "rules"` and `reason: "rule: <template>"`.
  2. **Laya** (only when `LAYA_CHECKPOINT` is set; one model behind a lock): `resolve_target` and `route_why` from `fastpath/decide.py`, the same decision code the eval harness uses. Laya handles chatter, synonyms ("the database" for Postgres) and casual-verb objects. Without a checkpoint, `RulesOnly` answers `llm` ("no rule matched").
  3. **Cloud**: everything else.

  Laya has no add_object answer, so objects are handled in code: `object_command` matches a narrow pattern ([fillers] verb [me] [a/an/one/another] [size] <one object> [here/please/on the board]). With a clear verb (draw/add/put/place/insert/sketch) the rule tier answers `fast`; with a casual verb (grab/get/have/bring/want/need/show) it goes fast only if Laya's `on_board` is true at the threshold ("let's grab a coffee" may be chatter), else LLM (`route_object`). Any other command naming a catalog object/alias (`draws_object`) goes to the LLM unless it was routed fast as an edit (update/move/delete/undo/clear). An import-time assert keeps object names/aliases off shape words (box, circle, note...).

## Conventions and gotchas

- **Element ids**: the model assigns short slug ids to new elements so later calls in the same turn can reference them. If a wanted id is taken, `allocateId` suffixes `-2` etc. and records it in `ctx.idMap`; always resolve refs through `resolve()` (id -> alias -> unique case-insensitive label match; else `ActionError`).
- **Top-level elements**: bound text labels (`containerId` set) are hidden from the model/summary via `isTopLevel`; read labels with `labelOf()`.
- **Shapes** store `customData.kind` (needed to tell `sticky` apart from `rectangle`). Updating a shape *rebuilds* it via `convertToExcalidrawElements` (keeps id/position/arrow bindings, bumps `version`) so labels re-wrap.
- **Arrows** are created with bindings to both ends (`startBinding`/`endBinding`, `boundElements` on the shapes) and are re-routed by `rerouteArrows` whenever a bound shape moves. They can't be moved directly. Arrows sharing both ends (A -> B with B -> A, or duplicates) get lanes (`arrowLanes`): parallel straight lines `LANE` 36px apart, centred on the line between the shapes, capped so each still starts inside both boxes (`connector(from, to, offset)`). `addArrow` and `deleteElements` re-route the pair, so the older arrow moves aside for a new one and back to the centre when its partner is deleted.
- `executor.ts` is **pure** (returns new arrays); `undo_last_command` is handled in `useCommandRunner`, not the executor (it throws if it reaches it).
- **Undo** = scene snapshot per command that changed the board (max 50), restored by bumping versions via `updateScene` with `CaptureUpdateAction.IMMEDIATELY`.
- AI-drawn elements use Nunito and `roughness: 0`; the palette is the named-colour map in `style.ts` (`COLORS` in `shared` must match its keys).
- Excalidraw needs `process.env.IS_PREACT = "false"` (set in `vite.config.ts`) and vitest inlines `@excalidraw`/`roughjs` deps. Tests set a fake text-metrics provider because jsdom has no canvas.
- **Auto-centre** (Settings `autoCenter`, default on, plain code, no model): after a command that changed the board, `consume` awaits `centerOn(lastTouched)`, the `touched` ids of the last board-changing action (a whole diagram for `generate_diagram`), placed at bottom centre of `safeArea` (`frame(..., AUTO_CENTER_ANCHOR_Y)` = 90% down it, clamped so the box stays inside; other callers of `frame` still centre) at the current zoom (zooms out only if it can't fit). Skipped after a `scroll_view` in the same command or a barge-in/undo/delete. Off = the old `revealIfHidden` (move only if it landed out of sight). The hook's default is off; `App` passes the setting.
- Board autosaves to `localStorage` key `voice-board:scene:v1` (400ms debounce).
- **Dev-only hook**: `window.__board.apply(text, actions)` (= `runner.applyActions`) runs actions through the same path as the model, so UI can be exercised without an API key.
- `StatusPill` shows the active Settings profile (`where`, model, key state); it exports `modelName()`: friendly names for Anthropic ids (`MODEL_NAMES`), `laya:*` ("Laya") and `rules` ("Rules"); the pill says "+ local" when a fast path is on (Node can't tell whether Laya is loaded); other models, including OpenAI ones, show their raw id.
- Fast-path sidecar gotchas: Excalidraw ids are random 20-char strings Laya never saw, so `/decide` aliases them to `e1, e2, ...` and maps actions back. With more than 10 elements the target question is dropped (Laya's head budget) and only the code rules pick targets. A laptop GPU clocks down when idle: a decision takes ~0.2 s back to back but ~0.4 s after a pause and 1.3 s after minutes idle; `FASTPATH_KEEP_WARM_S` removes the 1.3 s case. After `FASTPATH_IDLE_UNLOAD_S` (15 min) with no `/decide` request the housekeeping thread unloads the model (`router.unload`, frees VRAM, stops keep-warm); the next request starts a background reload and is answered `llm` ("fast path waking up"), later ones are fast again. Rule-tier commands (including non-casual objects and measurements) never need the model, so they still go fast while it sleeps. `/health` reports `awake`. A command over 30 words skips the model (`llm`). A command with a measurement (`has_measurement`: "10 ft", "20 meters"; no bare "in") never reaches Laya (it has no add_dimension): `measure_command` builds it in code or it goes to the LLM. It handles draw-verb + one object/shape + measurement (add it, then a height/width line), "the tree is 10 ft tall" (needs a height/width word and a `resolve_target` hit; resize words like make/move/by go to the LLM), and distances ("between X and Y", "X and Y are ... apart", "X is ... from Y", "between them" = two selected, else two most recent). Second measurement, second clause, speaker words (I/my/we) or an unresolved reference -> LLM.
- Root `dev` script uses `a & b`. On Windows npm runs scripts through `cmd.exe`, where `&` is sequential, so if the web app doesn't start run `npm run dev --workspace server` and `npm run dev --workspace web` in separate terminals. (Not verified on this machine.)
- `npm run format:check` on this Windows checkout flags ~18 files that were never touched (line endings from git autocrlf); check your own files with `npx prettier --check <files>`.
- Plot SVGs must be well-formed XML (a repeated attribute, e.g. two `fill`s on one `<text>`, makes the whole image fail to load silently); `plots.test.ts` checks every tag. SVG-in-`<img>` can't load web fonts, so plot text falls back to the system sans font.
- Excalidraw renders SVG images colour-inverted in dark mode (it resets the filter only for non-SVG), hence the PNG rasterizing in `objects.ts`. Emoji sets have no full-body child: `man`/`woman`/`person` are standing figures, `child`/`boy`/`girl`/`baby` are faces. Varieties are aliases of their category (rose -> `flower`, pine tree -> `tree`), not separate objects, to keep the `add_object` enum short. Aliases that clash with diagram words (box, user, notes, database...) were left out on purpose, and so was "graph" (now plot_graph); the curated `chart`/`bar chart` pictures remain, the prompt says charts are add_chart unless an icon is asked for.
- Moonshine (`moonshine-voice` 0.1.5) gotchas: it runs on CPU through its own onnxruntime, so it needs no VRAM. `MOONSHINE_ORT_SINGLE_THREAD=1` (undocumented; found in the native lib) cuts CPU from ~4 cores to ~0.5 with only ~0.2 s more delay. The `download`/`mic` CLIs want `--model-arch` as a number (4 = small streaming, 5 = medium streaming). `set_keyterms` only works with streaming archs, and terms can't contain commas. Line ids are 64-bit, so they're sent as strings. Measured on the 4800H with the test WAV (single thread): Small final text 0.46-0.81 s after speech, 314 MB; Medium 0.83-1.2 s, 503 MB.
- Testing voice without speaking: headless Edge with `--use-fake-ui-for-media-stream --use-fake-device-for-media-stream --use-file-for-fake-audio-capture=<wav>%noloop`, driven over CDP (`--remote-debugging-port`; click `button.mic` via `Runtime.evaluate` with `userGesture: true`). The fake device starts playing when it opens, before the page captures anything, so pad the WAV with ~1.5 s of leading silence or the first words are lost. To test the speech path alone, stream a WAV to the WebSocket from Python. Run the API server with `ANTHROPIC_API_KEY= OPENAI_API_KEY=` to avoid cloud calls; real env vars beat `--env-file`.
- Don't loop live Cerebras probes: the free tier's RPM limit is hit after a few calls and 429s for about a minute.
- Server tests never hit a real API: they pass fake SDK clients into `anthropicProvider`/`openaiProvider`.
